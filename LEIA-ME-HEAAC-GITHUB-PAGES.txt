COMO PUBLICAR NO GITHUB PAGES
1. Extraia o ZIP.
2. Publique o CONTEÚDO da pasta Radio-Caparao-Gospel-PWA como a raiz do site
   (ou como a pasta selecionada nas configurações do GitHub Pages).
3. Aguarde a atualização do GitHub Pages. Abri-lo em navegador normal mostra
   a tela de instalação; a interface e o autoinício são da PWA instalada.
4. Acesse /diagnostico.html no endereço publicado, clique em "Testar áudio".
5. Confirme no aparelho se há som. Instale/reabra a PWA.
6. Se a PWA antiga continuar em cache, force atualização, feche e reabra,
   ou remova e reinstale pelo navegador após a publicação.

SOBRE O STREAM HE-AAC
- A nova versão usa o HTTPS DIRETO como primeira tentativa no GitHub Pages,
  sem precisar configurar Cloudflare quando o browser aceita o áudio.
- O download contínuo observado ao abrir /; na barra de endereço é comum em
  SHOUTcast com AAC. Não garante sucesso do elemento HTML <audio>.
- Se o Chrome/Safari/Firefox não aceitar os cabeçalhos ou a codificação, é
  necessário mudar a configuração do servidor de streaming ou publicar o
  Worker opcional em cloudflare-worker/. Ele normaliza Content-Type e libera
  CORS ao retransmitir. Use /diagnostico.html para verificar.
- Sem CORS no servidor xCAST, o equalizador real de 24 bandas depende do proxy
  de mesma origem ou Worker; o tema e o componente permanecem presentes.
- O HTML5 Audio não pode obrigar um navegador a decodificar formatos não
  suportados. Um proxy apenas conserta cabeçalhos, não transcodifica HE-AAC.
- Validação externa do xCAST e áudio audível real NÃO foram realizadas neste
  ambiente. Os testes de código e simulações são descritos em TESTES-HEAAC.txt.

ESTRUTURA DO PACOTE
PWA estático com app.js, config.js, landing.js, estilos VERDES originais,
logotipo oficial, ícones, manifesto e service worker. server.js e scripts
INICIAR-* são opcionais e servem para testes locais; Github Pages não os executa.
cloudflare-worker/ é alternativa opcional para servidores incompatíveis.
