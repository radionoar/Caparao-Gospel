CORREÇÃO DO STREAMING
1. O arquivo listen.pls fornecido contém exatamente:
     File1=http://stm17.xcast.com.br:8318/;
   A versão anterior utilizava http://stm17.xcast.com.br:8318 SEM /;.
2. `config.js` e `server.js` agora usam a URL do listen.pls na íntegra.
3. O proxy Node aceita tanto respostas HTTP de áudio quanto o status
   antigo `ICY 200 OK` usado por servidores SHOUTcast.
4. Se o servidor devolver HTML em vez de áudio, o proxy informa erro 502
   em vez de entregar uma página indevidamente ao player.
5. Em sites HTTPS, havendo servidor Node por trás do mesmo domínio, o
   áudio passa pelo caminho HTTPS do aplicativo: /api/stream.

TESTE LOCAL NO WINDOWS
1. Extraia todo o ZIP para uma pasta, sem misturar arquivos da versão antiga.
2. Instale Node.js 20+ se necessário; execute INICIAR-WINDOWS.bat.
3. Abra http://localhost:8080/ no Chrome/Edge.
4. Instale o aplicativo pela tela de instalação e abra pelo ícone.
5. O app tenta tocar automaticamente ao abrir. Se o navegador bloquear,
   toque em LIGAR RÁDIO para autorizar o áudio.
6. Se ficar em RECONEXÃO, abra em outra aba:
   http://localhost:8080/api/stream
   Esse endereço deve receber áudio MP3/AAC, e não HTML nem erro 502.
   O log na janela Node explica falhas de rede/status do servidor remoto.
7. Confira no player VLC também o URL http://stm17.xcast.com.br:8318/;
   Se o VLC também falhar, o servidor/stream está offline ou bloqueado.

PUBLICAÇÃO HTTPS E GITHUB PAGES
- GitHub Pages é hospedagem estática; NÃO executa server.js.
- O streaming informado é HTTP. Navegadores em sites/PWAs HTTPS normalmente
  bloqueiam recursos HTTP (conteúdo misto), por isso somente corrigir /;
  não garante funcionamento no GitHub Pages.
- Para publicar em HTTPS, use hospedagem Node.js com domínio/HTTPS, fazendo
  /api/stream na mesma origem; OU peça ao provedor xCAST uma URL de áudio
  HTTPS permanente e comprovadamente funcional (ajuste `secureStreamUrl`).
- Não invente https://stm17.xcast.com.br:8318/;: pode não ter TLS.
- Não hospede o servidor Node diretamente na internet em HTTP puro.
