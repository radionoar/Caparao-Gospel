como Rádio Show Gospel de Colatina/ES, diferente de Rádio Caparaó Gospel.

  http://stm17.xcast.com.br:8318/;

O título da playlist NÃO prova que este endereço pertence à nova emissora.

FALHAS QUE PODEM GERAR "RECONEXÃO":
1. GitHub Pages não executa Node.js/server.js: /api/health não existe.
2. Streaming é HTTP, não pode ser reproduzido diretamente numa PWA HTTPS.
3. Origem xCAST está offline, endereço/porta errados ou rádio sem AutoDJ/DJ ativo.
4. Origem responde HTML/sem áudio, em vez do fluxo MP3/AAC.
5. O navegador pode bloquear reprodução automática sem toque; nesse caso toque
   no botão LIGAR. Nova versão evita montar Web Audio antes de gesto do usuário.

TESTE LOCAL (Node.js 20+):
  1. Execute INICIAR-WINDOWS.bat e deixe a janela aberta.
  2. Abra http://localhost:8080/diagnostico.html
  3. Clique "Verificar transmissão agora".
  4. Se validAudio:true, servidor remoto forneceu bytes de áudio.
  5. Se validAudio:false, a mensagem identifica o erro da origem.
  6. Instale a PWA no Chrome/Edge e abra pelo ícone. Se o navegador bloquear
     o autoinício, desligue e ligue o rádio com o botão da interface.

PUBLICAÇÃO:
  Em GitHub Pages (HTTPS), um link HTTP não toca de forma garantida.
  É necessário obter do provedor xCAST um URL HTTPS real de áudio, ou publicar
  o server.js em hospedagem Node.js com HTTPS no mesmo domínio do PWA.
  Quando o xCAST fornecer URL HTTPS real e compatível, preencher secureStreamUrl
  em config.js e incrementar versão do cache no sw.js / index.html / app.js.
  Não trocar http: por https: por conta própria sem testar suporte TLS.

A correção não consegue colocar no ar um streaming cujo servidor de origem
esteja offline. Nenhum teste real do domínio xCAST foi homologado aqui porque
este ambiente não dispõe de DNS externo para esse host.
