LAUDO DE ALTERAÇÕES HE-AAC — 08/11/2026

1. Problema comprovado no código anterior: aplicativo no GitHub Pages HTTPS
   considerava a rádio bloqueada porque config.js tinha apenas streamUrl HTTP
   e secureStreamUrl estava vazia. O proxy local não roda no Github Pages.
2. Novo dado do usuário: a mesma porta xCAST também aceita URL HTTPS e o
   streaming é HE-AAC 64 kbps 44,1 kHz. Quando aberto direto, baixa arquivo.
   Isso pode decorrer de tipo MIME/codificação; não equivale a áudio funcionando.
3. Corrigido config.js: secureStreamUrl = https://stm17.xcast.com.br:8318/;
   com HTTP original retido, proxy opcional, sem segredos.
4. app.js: HTTPS direto primeiro; rota Worker só depois de falha, quando
   configurada. Erros de codec HE-AAC 3 e 4 claramente identificados, sem
   reconexão infinita para uma falha permanente de formato. Preservado autoinício
   e recuperação automática de falhas de rede.
5. server.js (Node opcional) e worker.js: normalização de audio/aacp,
   application/octet-stream e audio/x-aac para audio/aac quando usados como
   retransmissão, sem transcodificação. Headers de saída inline e no-cache.
6. Diagnóstico próprio: verificação HE-AAC do navegador e player HTML5 de teste.
7. Tema: estilos verdes originais sem troca de paleta; apenas ajuste tipográfico
   para nome mais longo e alerta funcional para erro de compatibilidade.
8. Service Worker e URL de recursos versionados para atualizar PWA instalado.

LIMITAÇÕES E RISCOS
- O HE-AAC bruto poderá ser rejeitado por navegador/plataforma se o codec ou
  cabeçalho da origem não for reconhecido; não afirmar sucesso de áudio real.
- Sem CORS no xCAST, Web Audio API pode silenciar a reprodução; em streaming
  direto, análise real de 24 bandas fica desativada, mas o áudio tem prioridade.
- A ponte Cloudflare opcional depende de publicação externa. Não instalada.
- O ZIP não contém gravação nem retransmissão de músicas; só código da rádio.
