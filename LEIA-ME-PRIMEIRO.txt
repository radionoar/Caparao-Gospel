MUITO IMPORTANTE — VU METER E METADADOS NO GITHUB PAGES
O GitHub Pages é estático e NÃO executa server.js. Ao usar um servidor de áudio
HTTPS externo, o navegador só pode analisar as amostras para o VU meter se o
servidor externo permitir CORS (Access-Control-Allow-Origin), ou se um proxy
HTTPS controlado por você oferecer essa permissão.
O código usa o streaming HTTPS direto por padrão e NÃO abre o áudio em um grafo
Web Audio sem CORS. Se a tentativa CORS falhar, volta ao áudio nativo para
NÃO silenciar a transmissão; neste caso o VU meter fica parado (não simulado).
Os metadados do xCAST são consultados em /currentsong, /stats e /7.html;
se os endpoints não existirem ou não permitirem CORS, não será possível obter
esses títulos no GitHub Pages puro.
O pacote inclui código Cloudflare Worker para áudio CORS + leitura de metadados
via SHOUTcast (e fallback ICY); esse Worker PRECISA SER IMPLANTADO e testado
separadamente na sua conta Cloudflare para garantir essas funções sem CORS
originário. Consulte cloudflare-worker/COMO-PUBLICAR.txt.

NÃO É POSSÍVEL GARANTIR O ÁUDIO AO VIVO NESTE AMBIENTE
- A URL HTTPS foi confirmada pelo usuário no próprio navegador (download contínuo).
- O ambiente de compilação não consegue resolver stm17.xcast.com.br, então
  não houve validação da transmissão HE-AAC ao vivo.
- Os testes locais fizeram streaming AAC de exemplo, resposta ICY 200 OK,
  resposta de metadados e conferência de hash do tema original.
- O teste automatizado de interface Chromium local foi bloqueado pelo ambiente.

TESTE LOCAL OPCIONAL
Com Node.js 20 ou superior, execute INICIAR-WINDOWS.bat no Windows ou
INICIAR-LINUX-MAC.sh no Linux/macOS e acesse http://localhost:8080.
O proxy local proporciona CORS ao áudio, mas precisa alcançar o xCAST pela rede.
A tela do player só é exibida dentro da PWA instalada, como na base original.
